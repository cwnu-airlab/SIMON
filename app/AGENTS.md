# app

## Purpose
FastAPI backend for SIMON. Wires routers, manages the lifespan-scoped `httpx.AsyncClient` (vLLM) and `asyncpg` pool (PostgreSQL), and owns the schema for users, sessions, API keys, conversations, messages, and attachments.

## Key Files
| File | Description |
|------|-------------|
| `main.py` | FastAPI app factory: lifespan-managed httpx client, CORS, router registration, `/api/health` endpoint |
| `config.py` | `Settings` (pydantic-settings) loaded from `.env` — vLLM URL, DB path, session/cookie config |
| `database.py` | PostgreSQL via `asyncpg`. `create_pool()` (lifespan) + `get_db()` async context manager. `SCHEMA_SQL` covers six tables (users, sessions, api_keys, conversations, messages, attachments — last with `attachment_type`/`mime_type`/`width`/`height`/`byte_size` for image/pdf branching) with `CITEXT` username, `BIGINT GENERATED BY DEFAULT AS IDENTITY` ids, `TIMESTAMPTZ` timestamps. `_run_migrations` applies additive `ALTER TABLE … ADD COLUMN IF NOT EXISTS` so re-running is a no-op. |
| `__init__.py` | Package marker |

## Subdirectories

## For AI Agents

### Working In This Directory
- Always include `from app.config import settings` rather than reading env vars directly.
- Use the `get_db()` async context manager for any DB work — it acquires a connection from the asyncpg pool created at lifespan startup (`create_pool()`).
- New schema changes go in two places: append to `SCHEMA_SQL` for fresh DBs and add an idempotent `ALTER TABLE … ADD COLUMN IF NOT EXISTS` in `_run_migrations()` for existing DBs.
- The shared `httpx.AsyncClient` is on `app.state.http_client` (and the module-level `http_client`); reuse it for outbound calls instead of creating new clients.
- The asyncpg pool is on `app.state.db_pool`. Routers should not touch it directly — use `get_db()` instead.
- CORS is locked to `settings.origin` with credentials — adjust when adding cross-origin clients.

### Testing Requirements
- Run `uv run pytest tests/ -v` from the repo root.
- DB tests use a session-scoped testcontainers PostgreSQL (`tests/conftest.py` fixture `pg_dsn`); each test starts with `TRUNCATE … RESTART IDENTITY CASCADE` and uses a per-call `asyncpg.connect()` override of `get_db()` for cross-event-loop safety.

### Common Patterns
- Async everything (`async def` endpoints, `asyncpg`, `httpx.AsyncClient`).
- Routers are thin: parse Pydantic body → call `services.database` CRUD → return Pydantic response.
- Authentication is dependency-injected via `Depends(get_current_user)` (session cookie *or* `Authorization: Bearer` / `X-API-Key`) or `Depends(get_session_user_or_401)` (cookie only).

## Dependencies

### Internal
- Routers in `app/routers/` are mounted from `main.py`.
- `app.services.database` is the only module that talks to PostgreSQL directly.

### External
- `fastapi`, `httpx`, `asyncpg`, `pydantic-settings`, `uvicorn`
